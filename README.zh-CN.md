# Printscope

Excel 明明只有一小块数据，为什么会多打印几页空白？Printscope 从 `.xlsx` 文件结构里找线索，并告诉你下一步该在 Excel 里检查哪里。

[在线使用](https://yougan001.github.io/printscope/) · [English](README.md)

![工作簿诊断界面](docs/images/workspace.png)

## 怎么用

1. 选择一份 `.xlsx` 文件，切换到要检查的工作表。
2. 对照实际存储范围、有内容的单元格范围、候选可见范围和打印区域。
3. 阅读每条检查结果中的单元格位置、文件设置和下一步操作。
4. 需要记录时导出 JSON 报告；修改前在 Excel 的分页预览里核实。

网页默认打开一份真实样例：报表在 `A1:F24`，`M85` 有一个被 `;;;` 格式隐藏的数值，打印区域却延伸到了 M85。你可以下载这份样例，打开 Excel 自己验证。

## 能发现什么

- 有内容的单元格之外，还存着空白或只带格式的单元格。
- `;;;` 自定义格式、显式白色字体、隐藏行列中的数据。
- 错误单元格设置成“打印为空白”。
- 过大的固定打印区域、多个打印区域、手动分页符。
- 远离数据区域的绘图锚点。

白色字体不一定不可见；打印区域大，也不一定就是错误。检查结果会明确区分结构事实和需要人工核实的线索。

## 不做什么

不预测精确页数，不计算公式，不运行宏，不访问工作簿中的外链，不删除单元格，也不自动“修复”原文件。条件格式、主题颜色、合并单元格的实际显示宽度、打印机参数等没有完整模拟。候选可见范围不能直接当作新的打印区域。

## 隐私与限制

文件只在浏览器里处理，检查可以取消，不写入浏览器持久存储。报告不包含单元格值和公式正文，但会包含文件名、工作表名、地址和打印设置，分享前仍应检查。

支持未加密的普通 `.xlsx`，上限 20 MiB、50 个工作表、10 万个存储单元格、10 万条共享字符串、2 万种样式。不支持 `.xls`、`.xlsb` 和宏工作簿。超过限制或文件损坏时会停止，不输出残缺的“正常”报告。

## 本地运行

需要 Node.js 22.13 或以上。

```sh
npm ci
npm test
npm run dev
```

欢迎提交可复现的小样例。请勿把公司的报表或私人数据直接放进公开 issue；用虚构内容做一个能复现问题的最小文件即可。
