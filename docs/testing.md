# Verification notes

## Automated checks

25 tests cover ZIP bounds/checksums, duplicate/traversal entries, exaggerated and understated expansion, XML entities/namespaces/depth, macro rejection, ordinary and Strict namespaces, sparse extreme coordinates, 100,001-cell refusal, shared/inline strings, styles, hidden rows/columns, print areas, errors, breaks and drawing anchors.

A separate process removes the Node `Buffer` global before importing the core and inspecting the sample. This regression was added after an attempted standalone XML-validator migration imported Node-only code in a browser. The app keeps fast-xml-parser's built-in validator with one narrowly scoped deprecation annotation; validation is not disabled.

`npm test`, `npm run lint` and `npm run typecheck` passed locally. A native Windows build without a Pages base path completed once; a later Pages-mode Windows build exited nonzero during client output with no diagnostic. The Linux Pages workflow is the deployment gate. A Windows nonzero exit is not treated as success.

## Browser checks

- The initial report is generated by inspecting actual ZIP/XML sample bytes, not a canned report.
- Real file-input selection of a two-sheet fixture produced 14 stored cells. Keyboard selection of “Clean sheet” showed A1 only, zero findings, and a reminder that this does not guarantee page count.
- A damaged .xlsx showed a readable error and zero stale findings.
- A 100,000-cell fixture completed. A second real file-input change followed by the actual Cancel button stopped inspection; no old findings or report-export control remained.
- Actual JSON and XLSX downloads were read from disk. `node scripts/verify-downloads.mjs` confirms the JSON equals a fresh inspection of the downloaded workbook: 13 cells, two findings.
- At a 390-pixel viewport, document width equals viewport width. The mobile capture is 390 pixels wide, not a resized desktop screenshot.
- Desktop and mobile screenshots in `docs/images` were captured from the running app and visually inspected.

`node scripts/qa-fixtures.mjs` creates synthetic, non-sensitive workbooks in ignored `work/fixtures`. These do not replace testing on more real-world Excel/LibreOffice files. No native Excel pagination or printer-driver verification is claimed.

## Security and interpretation

This is not a comprehensive ZIP security audit or a full OOXML schema validator. Only requested XML parts are read, no archive paths are extracted, and relationships never trigger a network fetch. Imported text is rendered as text, not HTML. ZIP/XML and worker time limits bound the work; malformed or unsupported files can be rejected conservatively.

Candidate-visible bounds are based on a limited set of explicit hiding settings. They are deliberately not labeled as a correct print area. A distant drawing anchor does not prove that the object prints. Report consumers must keep the findings, evidence and limitations together.
